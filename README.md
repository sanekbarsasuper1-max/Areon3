# Areon frontend — минимальный скелет под areon-backend

Три реальных экрана, подключённых к бэкенду: вход, онбординг с проверкой
"Expose Public Match Data", профиль с реальными матчами из OpenDota.

## Запуск

```
npm install
cp .env.example .env   # проверить VITE_API_URL
npm run dev
```

Бэкенд (`areon-backend`) должен быть поднят на `VITE_API_URL` (по умолчанию
`http://localhost:3000`), и его `FRONTEND_URL` должен указывать сюда же
(`http://localhost:5173`) — иначе редирект после Steam-логина и CORS не
сойдутся.

## Экраны

Вход → онбординг → профиль → все матчи → **Match Analyzer** (клик по
любому матчу ведёт сразу сюда, без промежуточной карточки — так решили
в дизайне) → **база героя** (клик по имени героя в Match Analyzer).

Отдельная ветка: **Команды** — список своих команд, создание, страница
команды с составом и приглашением по Dota account_id, входящие
приглашения с принять/отклонить.

Отдельная ветка: **Турниры** — создание, регистрация команды,
организатор строит сетку и вводит результаты раунд за раундом. Сетка
показана простым списком по раундам, а не графической турнирной сеткой
— визуал bracket-диаграммы не делали, это отдельная задача поверх уже
рабочих данных.

Отдельная ветка: **Draft Trainer** — свободный драфт теперь настоящий
Captain's Mode: 24 шага по реальной структуре фаз банов/пиков (7-3-4
банов, 2-6-2 пиков), таймер на каждый ход (15с/30с, подтверждено
источниками), автоматический таймаут (бан — пропуск, пик — случайный
герой), полный Timeline на все 24 шага, состав команд Radiant/Dire,
поиск и фильтры по атрибуту/роли героя, экран DRAFT COMPLETE с кнопкой
"Новый драфт". First Pick и Radiant/Dire назначаются независимо (поле
`radiantSide`). Сетка героев теперь сгруппирована по атрибуту (Сила/
Ловкость/Интеллект/Универсальные) с цветовой маркировкой — как в
реальном клиенте Dota 2, вертикальными секциями вместо боковых колонок
(из-за узкого мобильного контейнера). Точный порядок ходов *внутри*
каждой фазы — размеченная реконструкция, не проверенный факт, см.
areon-backend/README.md. Плюс
просмотр реальных про-драфтов из OpenDota, **поиск соперника**
(очередь — оба нажали "искать", матч находится автоматически),
**приглашение конкретного онлайн-игрока** прямо на сайте — без ссылок,
приглашение появляется у другого человека само, обновления теперь идут
через WebSocket вместо опроса раз в 2с (см. areon-backend/README.md),
и **игра против AI-бота**
— фиксированная эвристика (случайные баны, пики по контрпикам из
реальных данных OpenDota), не обученная модель; бот ходит мгновенно,
без ожидания. На экране DRAFT COMPLETE — **разбор драфта**: оценка
состава по ролям/атрибутам/контрпикам (не прогноз победы), конкретные
пары "кто кого контрит" по реальным данным OpenDota, кого стоило
забанить лучше (когда есть данные), и честная пометка, что синергии
союзников по-прежнему не реализованы — источника данных для них просто
не существует.

На странице героя (`/heroes/:id`) — **рекомендации по предметам**:
реальный винрейт по недавним матчам на герое, не привязанный к
конкретному сопернику (для этого нет источника данных, как и для
синергий). Собирается вручную из админ-панели, не автоматически.

Отдельно: вкладка **"Драфты" в админ-панели** — список любых активных
партий на платформе (не только своих), переход на страницу партии в
режиме наблюдения, и кнопка **"Отменить ход (админ)"** — она нигде не
показывается обычным игрокам, отмены хода для них нет вообще. Отмена
теперь честно возвращает потраченное резервное время, а не просто
сбрасывает ход.

Отдельная ветка: **Поиск игроков** — фильтры по нику/рангу/линии/герою/
активности среди пользователей Areon (не всей Dota 2), с прямым
приглашением найденного игрока в драфт или в команду. Честно
предупреждает: линия (Safe/Mid/Off/Jungle) — не то же самое, что
позиция 1-5, регион и язык не фильтруются (не собираются вовсе).

Отдельная ветка: **Админ-панель** (`/admin`, видна только если
`me.isAdmin`) — статистика платформы, списки пользователей/команд/
турниров, кнопка полной синхронизации базы героев, и функции
поддержки: бан/разбан пользователя (сразу рвёт активную сессию, не
только новый вход), редактирование отображаемого имени, принудительное
закрытие зависшего турнира. Права выдаются только через
`ADMIN_STEAM_ID64` на бэкенде, в интерфейсе это никак не меняется.
Экран `/banned` показывается при попытке входа забаненного аккаунта —
но не мгновенно для уже открытой вкладки с существующей сессией, это
известное упрощение (см. areon-backend/README.md).

## Звуковая и музыкальная система

- **Архитектурный сдвиг**: то, что раньше было "разная фоновая тема на
  каждый раздел сайта" (home/statistics/tournaments), заменено на
  единый **глобальный музыкальный плеер** — пользователь сам ищет и
  ставит музыку, она играет на всех обычных страницах. Только вход в
  **режим** (сейчас — Draft Trainer; турниры зарезервированы на потом,
  как и в самом ТЗ) ставит GLOBAL на паузу и включает музыку режима.
- `src/audio/AudioManager.ts` — единственный владелец всего
  аудио-состояния: очередь GLOBAL-плеера, позиция, громкость, избранное,
  текущий режим, звуковые эффекты. Это plain-class синглтон, не
  React-компонент — намеренно: воспроизведение должно переживать смену
  страниц и повторные рендеры, чего не гарантирует состояние, привязанное
  к дереву компонентов. React обращается к нему только через
  `useAudio()`/`useMusicPlayer()`/`useAppMode()` в `AudioContext.tsx`.
- **Источник музыки — Jamendo** (`src/music/JamendoProvider.ts`),
  подтверждённый актуальный (сентябрь 2026) легальный API: полноценный
  стриминг (не 30-секундные превью), каталог Creative Commons, бесплатная
  регистрация `client_id`, CORS разрешён — можно обращаться прямо из
  браузера. Нужен `VITE_JAMENDO_CLIENT_ID` (см. `.env.example`,
  `FIRST_LAUNCH.md`) — без него поиск музыки просто ничего не находит,
  сайт не ломается.
- **Источник абстрагирован намеренно** (`src/music/MusicProvider.ts`) —
  `MusicManager` никогда не обращается к Jamendo напрямую, только через
  интерфейс `search/load/play/pause/resume/seek/setVolume/onEnded/
  onTimeUpdate`. Очередь, shuffle, repeat, избранное — логика самого
  менеджера, не провайдера, так что будущий провайдер (например, поверх
  Spotify Web Playback SDK) не должен заново реализовывать очередь.
- **Пауза/восстановление между GLOBAL и режимом — по спеке дословно**:
  вход в Draft плавно (900мс fade) гасит громкость GLOBAL, ставит его на
  **паузу** (не сброс, не остановку — позиция трека сохраняется), включает
  музыку режима. Выход — обратная последовательность, и **если GLOBAL уже
  был на паузе до входа в режим, он не запускается сам** —
  `wasPlayingBeforeMode` хранится именно для этого различия.
- **Персистентность**: очередь/позиция/громкость/shuffle/repeat —
  `localStorage` (личное состояние устройства, не синхронизируется между
  устройствами специально). **Избранное — на сервере** (`FavoriteTrack` в
  бэкенде, `GET/POST/DELETE /music/favorites`) — единственное, что
  реально стоит иметь на всех устройствах.
- **Честно не проверено живым запуском**: в отличие от Draft
  Trainer/Tournaments (которые гонялись через настоящий код десятками
  раз), здесь нет способа проверить реальное воспроизведение аудио и
  реальный ответ Jamendo без браузера и сети, которых в этой песочнице
  нет. Код рецензирован, не исполнен — как и вся Docker/BullMQ-инфраструктура
  ранее в этом проекте.
- Draft Trainer — SFX (бан/пик/фазы/таймер) **накладываются поверх**
  музыки режима, не мешая ей — каждый эффект это отдельный `Audio()`,
  громкость регулируется отдельным ползунком "Effects" от "Music".
- `/settings` — раздел Audio: Master/Music/SFX громкость раздельно,
  переключатели Music ON/OFF и SFX ON/OFF, сохраняется в `localStorage`,
  не включается автоматически после выключения.

Отдельная ветка: **Orion Trials** (`/trials`) — 10 испытаний на 5-дневный
цикл, прогресс-бары, серверный таймер обновления (не браузерный),
уведомление о выполнении (отдельное, более заметное — для LEGENDARY),
история прошлых циклов, баланс Orion Plus Shards (значок на профиле,
ссылка на `/trials`). Управление шаблонами испытаний — во вкладке
"Trials" админ-панели. Категории ABILITY и точный подсчёт мультикиллов
сознательно не реализованы — см. areon-backend/README.md, почему это не
временная недоделка, а честное следствие того, что парсится ~5% матчей.

## Сознательно не сделано в этом скелете

- Пагинация "Показать ещё" на экране "Все матчи" — сейчас грузится
  первая страница (до 50 записей на бэкенде), кнопки подгрузки следующих
  страниц ещё нет.
- Страница героя не показывает "хорошо сочетается с" (синергии) — на
  бэкенде это сознательно не реализовано, см. areon-backend/README.md.
- Никакой валидации/обработки ошибок сети сверх базового `try/catch` —
  этого достаточно для скелета, но не для продакшена.
- Приглашение в команду работает только по Dota account_id и только для
  тех, кто уже заходил в Areon — поиска игроков ещё нет (см. бэкенд).
- Ни изменения ролей/позиций в составе, ни выход/удаление из команды не
  вынесены на этот экран — соответствующие эндпоинты на бэкенде есть
  (`PATCH`/`DELETE /teams/:id/members/:userId`), UI под них ещё не собран.
- AI Draft, тренировочные сценарии и оценка драфта (Draft Analysis) не
  реализованы ни на бэкенде, ни здесь — см. areon-backend/README.md.
- Поиск героя ищет только по отображаемому названию — нет отдельного
  хранения алиасов/русских названий/сокращений (например "пудж" → Pudge)
  для полнотекстового поиска, как просил документ по доработке CM.
- 130-секундный резерв времени на сторону не реализован — только таймер
  на конкретный шаг.
- Undo не реализован.
- Стили — инлайновые, для скорости; в реальном проекте это уйдёт в
  компоненты дизайн-системы, а не в разрозненные `style={{...}}`.
